Current Implementation State

  • Home route renders a static AbreUSA shell.
  • Header includes brand and progress placeholder.
  • Main content supports future multi-step guided flow.
  • Reusable guided-flow and preview primitives support the current local flow shell.
  • Service selection is available for Complete Package and Florida LLC paths.
  • LLC name entry validates compatible suffixes locally.
  • Business activity selection uses existing prototype categories and local state only.
  • Member count selection supports 1 to 10 members and shows Single-Member / Multi-Member context.
  • Member data entry captures name, address, and ownership percentage per member in local state.
  • Business address entry captures street, city, state (FL), and ZIP in local state. Continue enabled when required fields are filled.
  • Registered Agent selection offers AbreUSA, self, or other; other reveals name and address fields in local state.
  • EIN questions step captures reason, entity type, responsible party name and passport number, start date, and fiscal closing month in local state.
  • Registered Agent Continue routes to EIN questions for Complete Package and to documents for Florida LLC.
  • Document collection captures passport and U.S. address proof, then uploads files to private Supabase storage after approval.
  • Placeholder/manual extraction fields are visible and editable for customer review.
  • Review screen maps local intake and document state into customer-facing sections.
  • Florida Articles preview appears for both active service paths; IRS SS-4 preview appears only for Complete Package.
  • Local approval gate requires explicit confirmation and states nothing is submitted yet.
  • Phase 6 payload boundaries and protocol/status assumptions are documented.
  • Confirmation screen displays a local protocol placeholder and AbreUSA review timeline.
  • Internal order payload is built locally; EIN data appears only for Complete Package.
  • Approved orders persist through a server-side /api/orders route; browser code no longer writes directly to Supabase tables.
  • Protocol numbers generated server-side via Postgres sequence (AUS-YYYY-NNNN); no client-side collision risk.
  • Applicant contact step (name, email, phone) added as step 2 of 13; persisted to applicants table in Supabase.
  • Document files upload to Supabase private storage through the server-side order route, and document rows are recorded for approved orders.
  • Production plan requires SUPABASE_SERVICE_ROLE_KEY before RLS and storage lockdown are applied.
  • Customer handoff uses the confirmation screen and persisted contact data; AbreUSA manual follow-up remains the MVP default.
  • Phase 6 exit criteria are met; remaining work is production hardening.
  • Production security plan requires server-side order persistence before RLS and storage lockdown.
  • No automated email, payment, public document URLs, or production RLS hardening yet.
